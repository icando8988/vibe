# MKT-011 — 콘텐츠 발행 준비 확인 양식

P1 / CX-DESIGN-01 / Master CX-MASTER-01 / 사용자 계속 진행 지시.

## 목적

MKT-009 편집 검토와 MKT-010 독자용 v2에서 대기 중인 Q1~Q6, 게시물별 승인, 이미지/권리 확인, 자동포스팅 프로그램 입력을 사용자가 한 번에 검토·답변할 수 있는 오프라인 양식을 만든다. 콘텐츠 마케팅을 막는 구체적인 입력을 구조화하되 답변을 대신 추정하지 않는다.

## 입력

- `docs/marketing/EDITORIAL_REVIEW.md` (질문 Q1~Q6, 위험·보류 사유)
- `docs/marketing/reader-content-pack.json` 및 `.md` (주제 3개/변형 9개, 상태·hold)
- `docs/MARKETING_DELIVERY_PLAN.md`
- 관련 결과 `.ai/results/MKT-009-CC-ENG-01.md`, `.ai/results/MKT-010-CX-DESIGN-01.md`

`API KEY.txt`, `SUPABASS DB 비번.txt`, `.env*`, 쿠키/토큰/비밀번호 파일은 읽거나 포함하지 않는다.

## 수정 허용

- `docs/marketing/publication-readiness.html` (신규)
- `docs/qa/MKT-011/README.md` (재현 설명만, 테스트 스위트 추가 금지)
- `.ai/results/MKT-011-CX-DESIGN-01.md`

그 외 web 앱, 기존 원고/팩/렌더러, 공용 `.ai` 파일, DB, 계정, 배포 설정 수정 금지. 앱이나 배포 사이트에 반영하지 않는다.

## 양식 요구사항

1. 한국어, 모바일·키보드 접근성 기본을 지킨 단일 오프라인 HTML. 외부 리소스/요청, 계정 입력, 자동 저장, 자동 발행을 추가하지 않는다.
2. Q1~Q6의 원문 질문과 보류 이유를 짧게 제시한다. 이름 사용 동의와 공개 글 승인, 거리 수치의 유효성과 게시 허가, 실제 준비자료 유무, 텀블벅 언급, 게시 주기 약속, E48 상품 사진 의미를 서로 섞지 않는다. 모든 질문에 `모르겠음/보류` 답변이 가능해야 한다.
3. v2의 12개 원문/채널 변형을 식별 가능한 형태로 각각 보여 주고, 각 항목에 `보류/수정 필요/이 항목은 승인 가능` 선택과 메모를 둔다. 기본은 전부 보류/미승인. 항목별 공개 승인은 사이트 실명 공개 동의와 별개라고 반복해 명시한다. 이미지·권리 자료가 필요한 항목을 식별하되 자료가 있다고 가정하지 않는다.
4. 자동포스팅 프로그램 수령 섹션: 소스 ZIP/저장소 링크, 버전, 라이선스, OS/런타임, 지원 블로그/Threads/Instagram 계정 유형 정보를 요청한다. 사용자가 공유할 때 `.env`, API 키, 비밀번호, 쿠키, 로그인 프로필/토큰은 빼라고 명확히 안내한다. 실제 자격정보 입력칸은 만들지 않는다.
5. 제출 기능은 현재 페이지에서 답변 JSON 파일을 로컬 다운로드하는 버튼만 허용한다. 다운로드 데이터는 답변만 포함하고 입력한 비밀정보가 없도록 화면에서 안내한다. 네트워크 전송, 서버 저장, 공개 승인 상태 변경, 미리보기에서 원문 승인 처리, 자동 게시 금지.
6. 모든 콘텐츠/프로젝트 사실을 source doc에 있는 계획/확인 상태로만 표기한다. 일정·실적·사진·수치·동의·출판 상태를 창작하거나 확정하지 않는다.
7. 응답 JSON 형식과 저장 파일명을 결과 보고서에 기록한다. 브라우저 자동화/테스트/테스트 스크립트 추가·실행은 하지 않는다.

## 완료 조건

허용 파일만 수정, 12개 항목 개별 답변 가능, Q1~Q6와 프로그램 입력이 포함됨, 기본 상태가 승인 아님, 오프라인 다운로드 외 외부 효과가 없다는 제한을 결과로 명시. 미확인 사실과 사용자 답변 대기 항목을 구분해 반환한다. 추가 위임·테스트·배포 금지.
