## 2. 정보 구조와 공통 표시

관리 진입점 안에 ‘게시 콘솔’을 둔다. 하위 목적지는 ‘내 콘텐츠’, ‘배포 작업’, ‘연결’, ‘결과 불명 대사’다. 초기에 관리자 한정 진입을 권고하며 작성자/승인자 분리는 기존 권한 계약 검토 후 확정한다. 상세 화면은 콘텐츠 또는 작업 제목을 가진 독립 페이지로 열어 새로고침/뒤로가기 후 위치를 복구한다.

기본 흐름: 내 콘텐츠 → 원본/버전 → 채널 초안 → 검증/승인 → 채널별 실행 확인 → 배포 작업 → 게시 증거/대사. 연결과 재인증은 이 흐름에서 왕복하되 복귀 시 같은 콘텐츠·버전·채널을 보여 준다. OAuth 복귀 자체를 승인이나 실행으로 취급하지 않는다.

공통 상단에는 화면 제목, 내 작업 범위, 마지막 갱신 시각·시간대, 현재 환경(모의/실제), 전역 실행 중지 여부를 둔다. 모의 결과는 항상 ‘모의 실행 완료 · 외부 게시 없음’으로 표시하며 실제 성공 집계에서 제외한다. 작업 수신/예약 저장/외부 게시 완료는 각각 다른 결과 문구를 사용한다.

### 상태 표시 계약

상태는 콘텐츠 검토, 채널 연결, 작업 결과를 독립 표기한다. stale·지연·재인증 보류는 기존 작업의 결과를 덮는 성공/실패 값으로 사용하지 않는 UX 보조 표시다. 최종 내부 명칭은 후속 데이터 계약에 맞춘다.

| 축/상태 | 배지 문구와 다음 행동 |
|---|---|
| 검토 필요 / approved | ‘검토 필요’ → 검토, ‘승인됨 · 원본 vN’ → 실행 준비 |
| stale | ‘원본 변경 · 재승인 필요’; 이전 승인 버전과 현재 버전 함께 표시, 실행 차단 |
| scheduled | ‘예약됨’과 예정 시각/시간대; 예약 저장은 게시 성공이 아님 |
| dispatching | ‘실행 중’; 재실행 불가, 진행 내역 보기 |
| published | ‘게시 확인됨’; 외부 ID 또는 검토된 HTTPS URL 및 확인 시각 |
| failed | ‘실패’; 원인·외부 게시 부재 확인 여부·허용된 다음 행동 |
| unknown | ‘결과 불명 · 대사 필요’; 자동/수동 재게시 액션 차단, 대사로 이동 |
| manual_ready / awaiting_evidence | ‘수동 게시 준비’ / ‘게시 증거 대기’ |
| abandoned / 취소 확정 | ‘수동 작업 중단’ / ‘예약 취소됨’; 외부 게시 삭제 의미 없음 |
| 재인증 보류 / 지연 / 전역 중지 | 원래 작업 상태와 나란히 표시, 원인·예정/실제 시각·복구 액션 |
| unverified | ‘기능 미확인’; readiness 결과 확인 전 실제 실행·예약 불가 |

색만으로 상태를 구분하지 않는다. 텍스트+기호+설명으로 표시하고 현재 토큰의 파랑 안내/주황 주의/적색 오류를 따른다. 새 성공 색은 필수 아님. 목록에서 짧은 배지를 쓰고 상세에는 이유·마지막 확인·다음 행동을 풀어 쓴다.

## 3. S1 — 내 콘텐츠 / 배포 작업 목록

**목적:** 편집할 원본과 처리해야 할 채널 작업을 혼동 없이 찾는다.

- 내 콘텐츠 행: 제목, 원본 최신 버전, 수정 시각, 검토 요약, 채널별 배지, 작성자(지원 확정 시), ‘편집’.
- 배포 작업 행: 콘텐츠 제목/고정 버전, 채널·대상 계정, 수동/실제/모의 구분, 작업 ID, 예정 시각·시간대, 상태+보조 경고, 마지막 갱신, ‘상세’.
- 제목/콘텐츠 ID/작업 ID/게시 URL·외부 ID 검색. 지원 검색 필드를 입력 도움말로 명시하고 본문 전체 검색은 MVP 약속에서 제외한다.
- 필터: 채널, 작업 상태, 검토 상태, 연결 문제, 실행 모드, 예정 기간. 기간이 예정 시각 기준인지 수정 시각 기준인지 명시한다. ‘내 콘텐츠’는 기존 소유권 범위 안에서만 조회한다.
- 기본 정렬은 배포 작업의 ‘조치 필요 우선’(unknown → 재인증/실패 → 지연 → 가까운 예약), 동률은 갱신 시각 최신순 제안. 콘텐츠는 수정 최신순. 사용자가 시각/제목 순으로 변경 가능하며 현재 정렬을 표시한다.
- 검색·필터·정렬·페이지 위치를 상세 왕복 시 유지. 필터된 건수와 전체 권한 범위 건수를 혼동하지 않게 표시한다. 필터 초기화와 페이지 이동을 제공한다.

**경계/실패:** 데이터 없음은 ‘첫 콘텐츠 작성’, 검색 결과 없음은 ‘필터 초기화’; 조회 실패는 ‘다시 불러오기’와 마지막 성공 시각. 로딩 중 0건 표시 금지. 이전 결과를 보이면 ‘갱신 실패 · 이전 조회 결과’로 명시한다. 권한 만료 시 데이터 노출을 멈추고 로그인 복귀 동선을 제공한다. 검색 문자열을 다른 사용자의 데이터 존재 여부 추론에 쓰지 않는다.

**접근성:** 검색 label, 필터 fieldset/legend, 결과 수 변경만 짧게 안내. 데스크톱 표의 열 제목과 정렬 상태를 전달한다. 행 전체 클릭 대신 제목 링크와 명확한 액션을 사용한다. 모바일은 같은 정보 순서의 카드 목록. 필터 적용 후 검색창 포커스를 강제로 옮기지 않는다.

**전이:** 목록 → 원본 상세/작업 상세/대사. 조회 재시도는 외부 게시 재시도와 구분한다. MVP는 일괄 게시/일괄 재시도를 제공하지 않는다.

## 4. S2 — 원본 편집과 버전 이력

**목적:** 채널들이 참조하는 승인 가능한 원본을 관리한다.

제목·본문·작성자·출처·링크·미디어/권리 근거, 현재 버전과 저장 시각을 표시한다. 본문 옆에는 채널별 영향 요약을 둔다. ‘저장하여 새 버전 만들기’, ‘채널 초안 보기’, ‘버전 비교’를 제공한다. 저장 전에는 ‘저장하지 않은 변경’으로 표시하며 영속 저장 성공 전에 저장됨을 표시하지 않는다.

버전 이력은 버전 번호·변경자·시각·변경 요약·연결된 승인/예약/결과를 보여 준다. 두 버전 비교는 제목/본문/링크/미디어/권리 변경을 텍스트로도 읽을 수 있게 한다. 과거 버전 복원은 새 버전을 만들며 과거 승인·게시 증거를 옮기지 않는다.

승인 후 저장 전 확인에는 영향을 받는 채널 초안과 미실행 예약 수를 구체적으로 표시한다. 저장하면 기존 참조는 stale 표시하고 실행을 차단하는 것을 권고한다. 새 버전에 채널 초안을 다시 준비하고 재승인·예약 재확인을 거친다. 실행 중/이미 게시된 이전 버전은 기록으로 보존하며 원격 내용이 바뀐 것으로 표시하지 않는다.

**경계/실패:** 동시 수정은 덮어쓰기 대신 ‘다른 변경이 저장됨’과 버전 비교/내 입력 보존. 저장 실패 시 입력 유지와 재저장. 미저장 이탈은 계속 편집/변경 버리기 확인. 빈 제목·본문, 권리 미등록, 유효하지 않은 링크는 해당 필드와 요약에 표시한다. 구체 검증은 다음 화면과 공유한다.

**접근성:** 필드 label·도움말·오류 연결, 최초 잘못된 필드로 이동 가능한 오류 요약, 변경된 줄을 색 외 텍스트로 구분. 버전 비교는 모바일에서 이전/현재 순서로 읽는다.

**전이:** 편집 → 저장 성공(새 버전) → 채널 검토 필요. 저장 실패/충돌 → 현재 편집 유지. 과거 버전 선택은 읽기 전용이며 승인 부활 없음.

## 5. S3 — 채널별 초안·미리보기·검증

**목적:** 같은 원본의 채널별 최종 공개 내용을 별도로 확인한다.

기존 라디오 채널 선택 패턴을 사용한다. 원본 vN을 고정 표시하고 채널마다 문안·미디어 순서/대체 설명·링크/UTM·대상 계정·검토 상태를 보여 준다. 블로그는 제목/본문, Threads는 문안, Instagram은 캡션/단일 이미지 우선으로 구성한다. 자동 문안 생성 기능은 본 배정에서 전제하지 않으며 채널 초안 준비 방식은 Master 결정이다.

데스크톱은 편집/미리보기 2열, 모바일은 편집 다음 미리보기. 미리보기는 ‘내용 검토용 · 실제 플랫폼 표시와 다를 수 있음’으로 표시한다. 특정 플랫폼 화면을 복제하지 않는다. 링크의 표시 문구·실제 목적지·최종 UTM URL을 같이 제공한다. 이미지가 없거나 로드 실패해도 파일명·대체 설명·권리 상태를 읽을 수 있어야 한다.

검증 결과는 ‘통과 / 수정 필요 / 미확인’으로 나눈다. 제목·본문 공백, 링크 형식, 권리 근거, 개인정보/사실/협찬 표기 검토, 미디어 준비 상태를 보여 준다. URL은 게시 증거와 초안 링크를 별도 구분한다. 길이·파일 형식/용량/비율·계정 조건·텍스트/링크/미디어 지원 수치는 readiness에서 확인한 값만 적용한다. 미확인 규칙을 통과로 간주하지 않는다. 확인 출처/확인 시각/적용 범위도 상세에서 볼 수 있게 한다.

**액션:** 저장, 검증 다시 확인, 검토 요청(역할 확정 시), 현재 채널 승인으로 이동. 한 채널의 편집은 그 채널 승인을 무효화한다. 원본 변경은 관련 모든 채널을 stale로 만든다. 다른 채널의 성공 기록은 유지한다.

**경계/실패:** stale 초안은 이전/최신 원본 비교 후 ‘새 버전 기준 초안 준비’; 기존 문안을 조용히 덮어쓰지 않는다. 미디어 업로드/처리 대기·실패는 개별 항목에 재준비 안내. 권리 근거 부족과 정책 unverified는 각각 별도 차단 이유. 미리보기 로드 실패가 게시 실패를 뜻하지 않는다.

**접근성/전이:** 채널 라디오는 키보드 기본 조작, 미리보기 영역에 채널명, 검증 요약에서 오류 필드로 이동. 초안 → 검증 → 승인, 변경 → 검토 필요. 기능 unverified여도 초안 보존/검토는 가능하나 실제 실행은 불가.

## 6. S4 — 승인·재승인 / 예약·즉시 실행 확인

**목적:** 누가 어떤 버전의 어떤 채널을 공개할지 명시적으로 확인한다.

승인 화면에는 원본/채널 초안 버전, 대상 계정, 최종 문안·미디어·링크, 사실·출처·권리 검토, 남은 경고를 표시한다. 승인자·시각·검토 버전은 승인 성공 후 표시한다. 미리 체크된 승인 동의는 사용하지 않는다. 승인과 게시 실행은 다른 액션이다.

예약/즉시 실행 확인은 승인된 채널별 행을 보여 주며 대상 계정, 고정 버전, 실행 방식, 시각과 IANA 시간대, 검증/연결 상태를 다시 확인한다. 블로그 행은 ‘수동 내보내기 준비’로 표시한다. 버튼 문구는 ‘Threads 예약 확정’, ‘Threads 지금 게시 요청’처럼 대상·행위를 명시한다. 복수 채널 요청을 제공하더라도 선택 대상별 결과를 반환하며 조용히 일부만 접수하지 않는다.

- 과거 시각, 존재하지 않거나 중복되는 현지 시각은 오류와 확정 시간대/오프셋 선택 안내. 즉시 실행은 예약 시각을 암묵적으로 덮지 않는다.
- 예약 시각은 화면에서 사용자 시간대로 표시하고 확인 화면에는 시간대와 오프셋을 함께 표시한다. 예약 변경 시 기존/새 시각을 비교한다.
- 실행 조건: 최신 승인, 권리 통과, 검증 통과, 확인된 기능, 유효 연결, 전역 중지 해제. 마지막 서버 재검사에서 변경되면 요청 차단과 새 상태 안내.
- 같은 콘텐츠·버전·채널·모드의 기존 작업이 있으면 새 생성 대신 해당 작업 링크. 버튼 잠금만으로 중복 방지를 설명하지 않는다.
- 재인증·시간 변경만으로 콘텐츠 재승인을 일괄 강요하지 않되 계정 변경은 승인 대상 재검토를 권고한다. 승인 유효 범위는 Master가 확정한다.

**경계/실패:** 확인 중 원본/초안 변경은 확인 화면 무효, 차이 확인 후 재승인. 접수 응답 유실 시 ‘접수 여부 확인 중’으로 기존 작업 조회, 게시 요청 반복 금지. 승인 권한 없음은 읽기/승인 요청 동선만 제공. 요청 중 닫아도 취소된 것으로 표시하지 않는다.

**접근성/전이:** 확인은 독립 페이지 또는 제목 있는 대화상자. 대화상자는 포커스 제한·Escape 닫기·원래 버튼 복귀, 기본 포커스는 제목 또는 안전한 액션. 승인 → 수동 준비 또는 예약/즉시 요청 → 서버가 확정한 작업 상태. 재승인은 이전 승인 이력을 보존한다.

## 7. S5 — 블로그 수동 내보내기·게시 증거

**목적:** 사람이 실제 블로그에서 게시한 뒤 확인 근거로 완료한다.

승인 버전/대상 블로그, 제목·본문·링크·미디어와 권리 체크리스트를 제공한다. ‘제목 복사’, ‘본문 복사’, ‘내보내기’는 지원 형식을 표시하며 형식 목록은 구현 단계에서 확정한다. 외부 글쓰기 화면은 명시적 외부 링크로 연다. 브라우저 자동 입력·CDP·자동 게시 UI는 없다.

`approved → manual_ready → awaiting_evidence → published | abandoned` 흐름을 표시한다. 내보내기 성공은 ‘내보내기 완료 · 외부 게시 확인 필요’다. 사용자가 ‘블로그에서 게시를 마쳤습니다’를 누르면 증거 입력으로 이동하며 그것만으로 성공 처리하지 않는다.

증거 입력은 HTTPS 게시 URL 또는 외부 게시 ID 중 하나 이상, 대상 계정/블로그, 확인자·확인 시각, 짧은 확인 메모를 받는다. URL과 ID의 형식·대상 일치 검토 결과를 보여 준 후 ‘게시 증거 확인 및 완료’로 확정한다. ID만 가능한 경우 사용자가 확인한 위치/방법을 메모하도록 권고한다. 링크 입력만으로 자동 검증 완료를 암시하지 않는다.

**경계/실패:** 복사 권한 거부는 선택 가능한 텍스트·수동 복사 제공. 다운로드 실패는 다시 내보내기이며 재게시가 아님. URL 오류/다른 계정/중복 증거는 입력 유지와 교정 안내. 게시했는지 모르면 ‘외부 게시 여부 확인 필요’로 대사 진입, 새 수동 게시를 유도하지 않는다. 작업 중단 확인은 이미 외부에 쓴 내용이 남을 수 있음을 알려 준다. stale 내보내기 자료는 재사용 경고와 최신 승인 동선.

**접근성/전이:** 복사 완료는 짧은 status, 외부 링크 새 창 여부 사전 안내, 증거 오류를 필드와 요약에 연결. 증거 저장 실패는 awaiting_evidence 유지, 성공 시에만 published. 증거 정정은 이전 근거와 정정 이유를 보존하는 검토 흐름으로 제안한다.

## 8. S6 — Threads/Instagram 연결과 readiness

**목적:** 연결된 계정과 실제 가능한 기능을 구분하고 만료로 인한 실행 중단을 복구한다.

채널별 카드에 계정 표시명/구분용 ID, 연결 상태, 마지막 확인, 확인된 만료시각(없으면 ‘확인되지 않음’), 권한 검토 상태, 게시·예약·대사·미디어 capability를 표시한다. 비밀 토큰·앱 시크릿 입력/조회/복사 UI는 제공하지 않는다. 만료일을 추정하지 않는다.

연결 UX 제안: 미연결 → 연결 시작 → 외부 인증 → 연결 확인 중 → 연결됨 또는 재인증 필요/실패. 기능은 별도로 unverified/확인됨/지원하지 않음을 표시한다. 연결됨이어도 readiness 미확인이면 실제 게시·예약을 막는다. 공식 검수·권한·매체 조건의 수치/지원 여부는 AUTOPOST-API-READINESS-001의 결과에 의존한다. Instagram은 단일 이미지 우선, 캐러셀/동영상/다중 계정은 후속으로 표시한다.

재인증 필요 시 영향받는 예약 목록, 예정 시각, 보류 이유와 ‘재인증’을 제공한다. 인증 완료 후 계정 일치를 확인하고 보류 작업을 다시 검토한다. 기한이 지난 작업을 한꺼번에 즉시 실행하지 않으며 ‘새 시각으로 예약 / 지금 실행 확인 / 취소’ 선택을 권고한다. 권한 복구와 unknown 해소는 별개다.

**경계/실패:** 인증 취소·만료·철회·다른 계정으로 복귀·연결 검사 실패를 구별한다. 다른 계정이면 자동 교체 없이 대상 비교와 다시 인증. 연결 해제 확인에는 영향받는 예약과 외부 게시물은 남는다는 점을 표시한다. 확인되지 않은 외부 삭제 기능을 약속하지 않는다.

**접근성/전이:** 외부 인증 출발/복귀 위치 설명, 복귀 시 제목과 결과 안내에 포커스, 긴 계정 ID는 줄바꿈/복사 가능. 재인증 보류 → 재확인 → 사용자가 확정한 새 실행 조건, 자동 게시 재개 금지 제안.

## 9. S7 — 결과 불명 대사 전용 화면

**목적:** 중복 게시 없이 외부 결과를 확정한다. 이 화면의 조회는 게시 요청과 분리한다.

상단 고정 문구: ‘외부 게시가 완료됐을 수 있습니다. 결과 확인 전에는 다시 게시하지 않습니다.’ ‘재시도’, ‘다시 게시’, ‘새 작업으로 복제’ 액션을 제공하지 않는다. 목록·상세·일괄 메뉴·재인증 복귀에서도 같은 차단을 적용해야 한다.

핵심 요소: 콘텐츠/초안 버전, 채널/계정, 작업 ID, 요청/시도/마지막 응답 시각, 알려진 외부 ID·URL, unknown 이유, 현재 연결/readiness, 비밀 없는 이벤트 이력, 이전 대사 기록. 확인 근거에는 확인자·시각·방법·대상 계정·조회 범위·관찰 결과·URL/외부 ID·판단 메모를 기록한다. 접근 자격정보와 전체 원격 응답은 받지 않는다.

공식 조회가 readiness에서 확인된 경우에만 ‘외부 결과 조회’를 제공한다. 불가/미확인이면 ‘직접 확인 후 근거 기록’을 제공한다. 조회 실패/권한 부족/미디어 처리 중/검색 결과 없음은 자동으로 게시 부재가 아니다.

| 선택 분기 | 필수 검토와 화면 전이 |
|---|---|
| published: 게시 확인 | 계정·버전·게시물 일치와 외부 ID 또는 검토된 HTTPS URL 확인 → 증거 요약 확인 → published. 내용/계정 불일치는 확정 차단 |
| absence: 게시 부재 확인 | 확인 방법·범위·시각과 부재 판단 근거 필요. 단순 timeout/검색 실패만으로 선택 불가. 권한 있는 검토자의 확인 후 ‘부재 확인 · 재실행 검토 가능’ 보조 표시. 내부 상태 매핑은 DATA 작업에서 확정 |
| still unknown: 여전히 불명 | 확인 시도와 미해결 이유 저장 → unknown 유지. 다음 확인 담당/시점 표시, 재게시 차단 유지 |

absence는 자동 재시도 허가가 아니다. 이후 별도 실행 확인에서 최신 승인·연결·권리·중복 여부를 재검사하고 명시적으로 재실행을 승인해야 한다. 기존 작업 재개/새 작업 생성 방식은 데이터 계약에 맡기며 사용자가 버전을 바꿔 차단을 우회하도록 안내하지 않는다.

**경계/실패:** 대사 중 늦은 성공 증거 도착은 최신 상태를 다시 읽고 충돌 비교, 이미 확정한 결과 덮어쓰기 금지. 동일 URL이 다른 작업에 있으면 중복/오연결 검토. 근거 저장 실패 시 unknown 유지. 관찰과 결론이 충돌하면 확정 불가. 정체된 dispatching도 운영 판정 전 실패로 단정하지 않는다.

**접근성:** 세 분기는 label 있는 라디오와 설명, 결론별 필수 필드를 문맥에 연결. 경고를 반복 낭독하지 않고 결과 저장/오류만 알린다. 이력은 시각순 텍스트 목록이며 키보드로 모든 근거를 볼 수 있다.

## 10. S8 — 작업 상세·혼합 결과·운영 중지

**목적:** 채널별 실제 결과와 남은 조치를 판단한다.

콘텐츠 요약 아래 채널별 패널을 동일 순서로 표시한다. 각 패널은 고정 버전·계정·상태·예약/실행/확인 시각·오류 요약·증거·다음 액션·이력을 가진다. 예: ‘3개 채널 중 게시 확인 1 · 실패 1 · 증거 대기 1’. 전체 ‘게시 완료’ 배지는 모든 선택 채널의 증거 확인 전 제공하지 않는다. 선택하지 않은 채널/모의 결과는 분모에서 제외하고 취소/중단은 성공으로 세지 않는다.

| 상황 | 안내와 주요 액션 |
|---|---|
| 일부 published | 성공 증거와 링크 유지. 실패 채널 복구가 성공 채널을 재게시하지 않음 |
| failed | 알려진 실패 이유와 수정 위치. 게시 부재가 확정되고 서버가 허용한 경우에만 해당 채널 재시도 확인 |
| scheduled 지연 | 예정 시각·현재 시각·마지막 확인·‘실행 대기 중/확인 필요’ 구별. SLA 수치 미확정 표시, 시간 초과만으로 재시도 금지 |
| dispatching 정체 | ‘외부 결과 확인 필요’; 대사 동선, 즉시 실패 전환 없음 |
| 재인증 보류 | 연결 복구 링크·영향 예약, 원래 결과 유지 |
| 취소 요청 | 처리 중/취소 확정 구분. 실행과 경합 시 ‘취소되지 않았을 수 있음’ 후 결과 조회/대사 |
| unknown | 전용 대사 화면만 제공 |
| 전역 실행 중지 | 중지 사유·시각·담당과 영향 채널, 이미 실행 중인 요청의 결과 확인 필요 |

운영자용 ‘새 실제 게시 실행 중지’ 확인은 영향 채널/예약 수와 진행 중 요청의 한계를 명시한다. 중지는 게시물 삭제가 아니며 재개는 이유·승인 기록과 보류 작업 확인을 거친다. 재개 시 밀린 예약 일괄 실행은 기본값으로 제공하지 않는다. 중지/재개 권한은 Master 확정 대상이다.

**접근성/전이:** 상태 갱신 시 패널 위치/포커스 유지, 변경 요약만 status로 안내. 폴링 시각을 매번 낭독하지 않는다. 취소 확인 후 서버 확정 상태만 표시하고 결과가 불명확하면 계속 조회/대사. 증거 외부 링크에는 채널·계정·버전을 알 수 있는 이름을 부여한다.

## 11. 공통 모바일·키보드·접근성·오류 기준

- 기존 design.css의 1180px 컨테이너와 700px 편집 1열/960px 헤더 패턴을 따른다. 320 CSS px에서도 본문 가로 넘침 없이 긴 URL/ID 줄바꿈. 목록은 카드, 채널은 라디오 줄바꿈, 확인 요약은 세로 순서로 제공한다.
- 모바일에서 핵심 상태·다음 행동·버전을 접힌 부가정보 안에 숨기지 않는다. 하단 고정 액션을 도입하면 키보드·확대·오류를 가리지 않도록 하며 우선 일반 문서 흐름 액션을 권고한다.
- 기존 본문 바로가기/단일 main/h1/한국어 문서를 유지한다. 조작 영역은 최소 44px, 기존 주요 버튼 50px와 필드 48px 기준을 따른다. 키보드만으로 검색→편집→승인→예약→대사까지 도달해야 한다.
- 현재 3px 포커스 링을 유지하고 색 대비는 구현 시 WCAG AA 기준으로 확인한다. 기존 색 토큰 사용만으로 대비 통과를 선언하지 않는다. 확대 200%에서 정보/액션 소실 금지, reduced-motion/forced-colors 지원 계승.
- 드래그 미디어 순서 변경에는 ‘위로/아래로’ 버튼 대안. 이미지 설명/장식 구분. 아이콘 단독 액션에는 접근 가능한 이름.
- 처리 중 버튼은 동작과 대기 문구를 제공한다. 영구 차단 버튼은 wait 커서를 쓰지 않으며 옆에 이유와 해결 링크를 둔다. 색/hover/tooltip만으로 차단 이유를 전달하지 않는다.
- 초기 로딩은 ‘불러오는 중’, 빈 목록은 다음 행동, 부분 조회 실패는 실패 구획과 재조회, 전면 실패는 재조회/복귀. 조회 오류를 실제 게시 실패 배지로 바꾸지 않는다.
- 세션 만료/권한 철회는 민감 데이터 노출 중지, 안전한 복귀 경로 안내. 미저장 입력의 재인증 후 복원 여부는 보안 정책에 따라 구현 전에 확정하며 임의 브라우저 영속 저장을 약속하지 않는다.
- 오류에는 무엇이 실패했는지·사용자가 할 일·안전한 참조 ID를 표시한다. 토큰/시크릿/원격 응답 원문/프롬프트는 표시하지 않는다. 오류 요약으로 이동 가능한 필드 연결과 필요한 경우 alert를 제공한다.
- 파괴적/영향 큰 액션(미저장 변경 버리기, 예약 취소, 연결 해제, 미디어 삭제, 실행 중지/재개)은 대상·수량·남는 외부 결과·되돌릴 수 있는 범위를 확인한다. ‘확인’ 대신 구체 버튼 이름을 쓴다. 취소 버튼을 먼저 안전하게 제공한다.
- 미디어 삭제는 게시/예약 참조·권리/보존 정책 확인 전 진행할 수 없게 한다. 외부 게시물 삭제와 로컬 미디어 삭제를 별도 설명한다. 기본 30일 일괄 삭제 같은 정책은 도입하지 않는다.

## 12. 제출 검토와 한계

배정 범위 1은 S1, 2는 S2/S3, 3은 S4, 4는 S5, 5는 S6, 6은 S7, 7은 S8, 8은 각 화면과 공통 기준에 대응한다. 각 화면의 목적·요소·액션·경계·접근성·상태 전이를 문서 자체 대조로 검토했다.

수정 산출물은 본 문서 하나다. 구현 코드·DB·SQL·이미지 자산·테스트를 만들거나 실행하지 않았다. API 정책을 추가 조사/추정하지 않았고 최신 지원 여부 검증은 readiness 작업에 남겼다. 브라우저 렌더링·실계정·예약 실행·성능·접근성 도구 검증은 미실행이며 본 제출은 운영 성공 증거가 아니다. Master는 사용자/기존 승인과 권한 계약을 대조하고 ready_review 결과를 통합해야 한다.

## 14. 권장 구현 순서

1. Master가 위 권한·승인 범위·대사 권한을 확정하고 AUTOPOST-API-READINESS-001 및 AUTOPOST-DATA-001과 상태/보조 표시를 정렬한다. 키트 참조 없는 독립 설계 범위를 유지한다.
2. 기존 관리 진입점 안에서 공통 레이아웃·접근 차단·내 콘텐츠/작업 조회·원본 버전·채널 검증/승인을 구현한다. 모의/실제 표시를 처음부터 분리한다.
3. AUTOPOST-MANUAL-BLOG-001로 수동 준비→내보내기→증거→published/abandoned를 연결한다. 저장·승인·증거 흐름을 먼저 완성한다.
4. API 실제 실행 전에 unknown 대사·혼합 결과·연결/재인증·예약 보류·중지/취소 경합 UX를 구현하고 데이터/운영 담당과 차단 조건을 맞춘다.
5. readiness/보안/권리 또는 clean-room 경로가 확정된 후 Threads 텍스트, 다음 Instagram 단일 이미지 순으로 실제 기능을 연결한다. 미확인 기능은 계속 차단한다.
6. AUTOPOST-OPERATIONS-001에서 SLA·알림·보존/삭제·재개 운영을 확정한다. 구현 작업의 별도 착수 지시 이후 모바일/키보드·오류/경합·실계정 검증을 수행하며 배포/실게시 승인은 별도 범위다.
