# SNS 관리 통합 개발 계획

공통 원고 한 건에서 Threads, Instagram, 네이버 블로그 초안을 만들고, 관리자가 채널별로 검토한 뒤 게시 작업을 관리한다. 기존 세 프로그램에서 이미 구현한 생성·게시 기능을 현재 사이트의 관리자 권한, 원고 버전, 승인, 게시 증거 흐름에 연결한다.

| 순서 | 연결할 기능 | 완료 기준 |
|---|---|---|
| 1 | 상단 SNS 관리와 기존 콘솔 연결 | 새 원고, 보관함, 게시 작업, 채널 연결로 직접 이동할 수 있고 승인된 관리자만 콘솔 데이터를 볼 수 있다. |
| 2 | 세 채널의 텍스트 초안 생성 | 원본의 생성 모듈을 현재 원고·채널 형식에 연결한다. 결과는 편집 가능한 새 초안으로 저장되며 생성 실패가 저장 성공으로 표시되지 않는다. |
| 3 | 네이버 블로그 게시 | 기존 확장으로 승인본을 입력하고 관리자가 실제 발행한 URL을 기록한다. 홈의 블로그 카드에서 그 URL을 열 수 있다. |
| 4 | Threads 텍스트 실제 게시 | 로컬 워커의 최종 승인 기록 검수와 실제 DB 연결 두 개의 경합 검증을 마친 뒤 실계정 게시 1건에서 외부 ID·URL을 대조한다. |
| 5 | Instagram 단일 이미지 게시 | 원본 게시 흐름과 기존 OAuth·미디어 연결을 붙인다. 승인된 이미지의 전달, 게시 결과와 외부 URL을 실계정에서 확인한다. |
| 6 | 예약 게시 실행 | 기존 예약 디스패치의 동작을 현재 DB 선점과 복구 계약에 연결한다. 도래 작업만 선택하고 중단·취소·응답 유실에서 중복 게시가 발생하지 않는지 확인한다. |

생성 코드의 기준은 Threads·Instagram 원본의 `src/lib/ai/generator.ts`와 Blog 원본의 생성·편집 경로다. 게시 코드는 Threads·Instagram 원본의 예약 디스패치와 현재 VIBE의 게시 클라이언트, 네이버 확장 인계 경로를 기준으로 한다. 각 모듈이 의존하는 계정, 설정과 데이터 구조는 통합 앱의 계약에 맞춘다.

텍스트 생성 서버 연결은 기존 Backend에 배정했다. 계약 검토 뒤 Front가 관리자 초안 편집 화면을 연결한다. Threads 실행기의 최종 승인 기록은 독립 검수 중이며, Instagram과 예약 게시에서는 검수가 끝난 게시 작업 계약을 재사용한다. 운영 검증 전에는 채널의 실제 게시를 활성화하지 않는다.
