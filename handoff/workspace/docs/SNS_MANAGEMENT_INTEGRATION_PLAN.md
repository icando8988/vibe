# SNS 관리 개발 확장 플랜

## 목표와 작업 흐름

SNS 관리에서 글감을 수집하거나 주제를 직접 입력한다. 공통 원고를 만든 뒤 Threads 문안, Instagram 캡션·이미지, 네이버 블로그 글로 변환한다. 관리자가 채널별 결과를 검토하고 승인하면 연결된 계정으로 즉시 또는 예약 발행한다. 작업 목록에는 승인본, 예약 시각, 실제 게시 결과와 링크를 기록한다.

대시보드 첫 화면에 원고 시작, 콘텐츠 보관함, 게시 작업, 계정 연결을 둔다. 조회 성공·0건·조회 실패를 구분하고 승인 대기, 예약, 게시 확인, 조치 필요를 구분한다. 활성화되지 않은 기능에는 준비 상태와 필요한 설정을 표시한다.

## 제공 소스와 현재 VIBE의 연결점

| 채널 | 원본에서 확인한 기능 | VIBE의 현재 상태 | 붙일 기능 |
|---|---|---|---|
| Threads | `lib/ai/collector.ts`, `generator.ts`에 글감 가공·문안·이미지 생성이 있고, `lib/posts/publish-core.ts`, `dispatch.ts`, `api/posts/dispatch-scheduled`에 발행·예약 실행이 있다. | OAuth, 채널 초안, 모의 실행은 배포됐다. 실제 텍스트 실행기와 최종 승인 기록은 로컬 검수를 통과했다. | 실제 요청을 보내는 실행 경로, 즉시·예약 작업, 승인된 계정과 실게시 결과를 연결한다. 이미지 게시를 후속으로 추가한다. |
| Instagram | `lib/ai/generator.ts`에 캡션·해시태그·이미지·카드뉴스 생성이 있고, `lib/posts/publish-core.ts`, `dispatch.ts`, `api/cardnews/instagram/publish`에 단일·카드뉴스 발행 경로가 있다. | OAuth와 초안 편집, 단일 이미지 게시 클라이언트 부품이 있다. | 승인 이미지 전달과 처리 상태 확인, 실제 발행·예약을 단일 이미지부터 연결한다. 이후 캐러셀을 추가한다. |
| 네이버 블로그 | `api/candidates/*`에 RSS·웹·화제·쇼츠 수집, `api/auto-post`에 제목·본문 생성과 자체 보관함 저장, 확장에 스마트에디터 입력과 발행 설정이 있다. | 수동 게시 작업, 확장 인계, 게시 URL 증거와 홈 연결이 있다. | 생성·편집·확장 인계를 연결하고 실제 글 한 건의 게시 URL과 홈 노출을 검증한다. 기존 키트에 없는 최종 자동 발행은 별도 소스 또는 지원되는 연결 경로를 확인한다. |

제공된 블로그 확장은 최종 발행 버튼을 누르지 않는다. 네이버는 기존 로그인 방식 블로그 글쓰기 API를 종료했다. 완전 자동 발행 코드가 따로 있다면 해당 모듈과 사용 조건을 확인한 뒤 네이버 작업에 연결한다. 그동안 확장 입력 완료와 실제 발행을 화면에서 다른 상태로 표시한다.

## 구현 순서와 완료 기준

| 단계 | 구현 및 담당 | 완료 기준 |
|---|---|---|
| 1. 운영 대시보드 | Front·Design. 원고 시작, 보관함, 채널별 연결, 예약·게시 작업을 연결한다. | 관리자만 접근하며 실제 원고와 작업 데이터, 조회 오류, 빈 상태가 구분된다. |
| 2. 공통 원고 입력 두 경로 | Backend·Front. 주제 입력으로 제목·본문을 미리 보고 공통 원고에 저장한다. 글감 후보는 메모·등록 RSS·웹 출처부터 추가하고, 화제 검색과 쇼츠 분석을 공급자별로 붙인다. | 후보 선택과 주제 직접 입력이 같은 원고 편집기로 이어진다. 후보의 출처·수집 시각·지표 근거를 보존하고, 동일 후보의 중복 등록을 막는다. |
| 3. 채널별 생성과 미디어 | Backend·Front. 배포된 텍스트 생성 화면에 사용량 제한 DB, 운영 AI 소스와 이미지 저장을 연결한다. | 승인된 공통 원고 한 건에서 선택한 채널 초안이 각각 생성된다. Vercel/Supabase에서 사용량 한도와 동시 요청을 확인한다. 검토 전에는 승인·발행 상태가 바뀌지 않는다. |
| 4. 실계정 발행 | Backend·Tester. 네이버 확장 인계, Threads 텍스트, Instagram 단일 이미지를 각각 검증한다. | 실계정 한 건씩 결과 ID와 URL을 대조한다. 확정 실패, 게시 여부 불명, 응답 유실은 별도 상태로 남고 무조건 재시도하지 않는다. |
| 5. 예약 실행 | Backend·Tester. 제공 키트의 예약 실행을 VIBE 작업 선점·최종 승인·정지·복구 계약에 연결한다. | 시간대가 표시되고 승인된 예약만 실행한다. 취소·계정 철회·중복 실행·응답 지연에서 게시가 중복되지 않는지 실제 DB 연결 두 개로 확인한다. |
| 6. 확장 기능 | Front·Backend. Threads 이미지, Instagram 캐러셀·카드뉴스, 네이버 추가 발행 경로를 순차 연결한다. | 각 채널이 지원하는 미디어·게시 결과를 별도 인수한다. |

## 운영 인수

- AI 사용량 제한 마이그레이션과 모델·API 설정을 확인한 뒤 채널별 한 건씩 생성·저장한다. 모델 비용과 앱 요청 수를 따로 확인한다.
- Threads·Instagram은 제공 소스에서 확인한 게시 흐름을 재사용하되 VIBE의 승인, 계정 권한, 작업 버전·증거 계약을 적용한다. 코드 이식에 필요한 재사용 권리와 공급자 설정은 해당 모듈을 붙이기 전에 확인한다.
- 채널별 계정, 운영 배포 커밋, 적용 DB 버전, 실제 게시 URL과 예약·취소 결과를 공식 작업표에 기록한다.
- 원본 `/quick` 흐름은 주인님 스크린샷을 참고했다. 외부 사이트의 로그인 세션 안쪽 화면은 확인하지 못했다.
