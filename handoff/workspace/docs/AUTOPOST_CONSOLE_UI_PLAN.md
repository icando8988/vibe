읽은 입력: `AI_TEAM_RULES.md`, `.ai/PROJECT.md`, `.ai/TEAM.md`, `.ai/TRANSPORT.md`, `.ai/roles/CODEX_SUB_UI.md`, `docs/AUTOPOST_INTEGRATION_PLAN.md`, `.ai/results/AUTOPOST-UX-001-CX-DESIGN.md`, `.ai/results/AUTOPOST-API-READINESS-001-CC-ENG.md`, `.ai/results/AUTOPOST-DATA-001-CC-ENG.md`; 현행 `web/src/components/site-header.tsx`, `web/src/app/admin/page.tsx`, `web/src/components/content-distribution-preview.tsx`, `web/src/lib/distribution/types.ts`, `web/src/lib/distribution/adapters.ts`, `web/src/app/globals.css`, `web/src/styles/design.css`. 최근 도메인 변경은 `.ai/results/AUTOPOST-M2-APP-001-CC-ENG.md`, `.ai/results/AUTOPOST-MANUAL-BLOG-APP-001-CC-ENG.md`의 앞부분(공개 계약·제약·미검증 보고)을 보충 참조했다. 모두 로컬 텍스트 정적 열람이다. 키트 소스·화면·자산·자격정보·비밀번호·환경파일은 읽거나 재사용하지 않았다.

## 2. 추천 정보구조와 탐색

메뉴명은 **콘텐츠 배포**, 콘솔 제목은 **콘텐츠 배포 콘솔**을 권고한다. ‘자동 포스팅’보다 수동 블로그·모의 실행·준비 전 API를 함께 설명하기 쉽다. 채널별 독립 앱 메뉴 세 개 대신 콘텐츠와 작업을 중심에 두고 채널은 초안 목적지와 목록 필터로 제공한다.

```text
공개 사이트
  /                     홈
  /about                도전 이야기
  /stories              이야기 목록
  /how-it-works          참여 안내
  /books                책 준비 안내
  /login                회원 이용 안내
인증된 이용 영역 → 권한 확인 후 관리 진입(노출 위치는 회원 영역 권고)
  /admin                관리 홈
    콘텐츠 배포          ← 단일 발견 지점, 준비 상태를 설명하는 카드
      /admin/distribution                  통합 개요
      /admin/distribution/contents         콘텐츠
        /new                               새 원문
        /[contentId]                       원문·버전·3채널 요약
        /[contentId]/channels/[channel]     채널 초안 편집
        /[contentId]/channels/[channel]/review  승인 검토
        /[contentId]/prepare                선택 채널 실행 준비 비교
      /admin/distribution/jobs             예약·작업 큐
        /[jobId]                           실행 상세·증거
        /[jobId]/manual                     Blog 수동 준비·증거
        /[jobId]/reconcile                  대사·오류 검토
      /admin/distribution/connections       연결·기능 준비도
      /admin/distribution/media             미디어·권리
        /[assetId]                         자산 상세·권리 검토·참조 작업
```

대표 경로는 제안이며 아직 구현되지 않았다. `[channel]`은 blog/threads/instagram 허용목록만 사용한다. 배포 원문과 공개 이야기의 발행은 서로 다른 도메인이다. 공개 이야기가 있으면 참조할 수 있지만 원문 저장으로 사이트나 외부 채널에 공개하지 않는다. 다른 관리자 기능(회원·입금·알림)은 DEV-007 범위이며 이 작업에서 새 메뉴 구조를 확정하지 않는다.

**데스크톱:** 기존 공개 헤더 아래 ‘관리 / 콘텐츠 배포 / 현재 화면’ 경로, 관리로 돌아가기, 왼쪽 콘솔 메뉴(개요·콘텐츠·예약/작업·연결·미디어/권리), 오른쪽 본문을 둔다. 개요의 조치 필요 구획에서 결과 불명 대사를 쉽게 찾되 별도 채널 앱으로 분리하지 않는다. 채널 편집 화면에서는 원문 복귀와 세 채널 링크를 상단에 두고 현재 채널을 명시한다.

**모바일:** 960px 이하 헤더가 세로로 재배치되는 기존 패턴을 따른다. 콘솔 메뉴를 본문 앞의 ‘콘텐츠 배포 메뉴’ details/summary로 접어 열고, 현재 화면 이름은 접힌 상태에도 보인다. 700px 이하 모든 편집·미리보기·채널 비교를 한 열로 표시한다. 모바일에서는 별도 좁은 가로 탭을 강제하지 않고 채널명·검토·실행 상태가 있는 세로 링크를 쓴다. 하단 고정 버튼은 초기 범위에서 제외해 키보드와 확대 화면을 가리지 않게 한다. 목록→상세→뒤로가기에서 검색/필터/페이지 위치를 URL 상태로 보존한다.

**정보 우선순위:** ① 관리 영역/현재 콘텐츠·버전 ② 모의/수동/실제 모드와 준비 전 안내 ③ 승인·연결/readiness·결과를 분리한 상태 ④ 지금 할 수 있는 행동과 차단 이유 ⑤ 문안·미디어·대상 ⑥ 승인/시도/증거 이력. 로그나 해시는 기본 편집보다 아래에 둔다. 긴 ID는 줄바꿈하고 상세에서만 전체를 노출한다.

## 3. 역할과 권한

통합 플랜 D1에 따라 배포 권한은 **admin 역할 AND approval_status=approved**다. 기존 전역 admin 판정의 의미를 변경하지 않고 배포 전용 서버/DB 판정으로 추가한다. 화면 숨김만으로 허용하지 않는다. 모든 조회·저장·승인·증거·실행 요청마다 서버가 재검사하고, DB RLS/grants와 허용 RPC를 적용해야 한다.

| 사용자 상태 | 탐색과 데이터 | 행위 |
|---|---|---|
| 비로그인/인증 미설정 | 관리자 안내만. 운영 메뉴·건수·콘텐츠 미노출 | 로그인 안내 또는 인증 준비 안내 |
| 일반 회원/승인 대기/거절·정지 | 배포 콘솔 접근 불가. 직접 URL도 동일 차단 | 회원 영역으로 복귀 |
| admin이나 승인되지 않음 | 전역 관리 권한과 별개로 배포 거부 | 승인 상태 확인 안내; 배포 데이터 미노출 |
| 승인된 admin | 배포 데이터 조회, 권한 있는 작업의 준비·검토 | 서버 기능이 준비된 범위에서 원문/초안/승인/수동 증거/대사. live는 추가 게이트 필요 |
| 서버 워커 | 사람용 메뉴·브라우저 계정 아님 | 선점·시도·전이, 비밀과 원격 호출은 서버 전용 |

작성자/승인자/운영자 세분화와 자기 승인 금지는 후속 정책이다. 현재 MVP에서 가상의 새 역할을 부여하지 않으며 승인 actor·시각·대상 버전을 기록한다. 세션 만료/권한 철회 시 민감한 화면과 캐시를 숨기고 인증 복귀를 안내한다. 미저장 초안을 브라우저 영속 저장하는 정책은 확정하지 않았다.

## 4. 대표 사용자 흐름

### A. 공통 콘텐츠에서 교차채널 준비

관리→콘텐츠 배포→콘텐츠 목록→원문 선택/새 원문→원문 저장(서버 확인 시에만 저장됨)→원문 버전 검토→Blog/Threads/Instagram 초안 링크→각 채널 편집/미디어·권리·링크 검토→개별 승인→선택 채널 준비 비교→가능한 채널별 다음 단계→작업 상세.

공통 원문이 먼저다. 채널 편집을 독립 앱으로 열지 않는다. 단일 채널 편집은 링크 탐색, 복수 채널 선택은 준비 비교 화면의 체크박스로 구분한다. 모두 선택은 기본값이 아니며 채널별 승인·대상·모드·차단 이유를 확인한다. 준비 전 채널도 초안 목적지로 이동할 수 있지만 실제 실행 버튼은 비활성이다. 초안 저장/승인 UI 자체도 백엔드 미연결이면 ‘저장 준비 전’ 사유를 표시한다.

복수 선택은 한 번에 게시하는 트랜잭션을 뜻하지 않는다. MVP는 **채널별 확인 버튼**을 권고한다. Blog는 ‘수동 배포 준비’, Threads/Instagram은 향후 ‘모의 실행’ 또는 게이트 통과 후 ‘게시 요청/예약 확인’. 여러 채널 자동 접수는 후속이며 부분 접수를 조용히 처리하지 않는다. 결과는 선택한 채널·콘텐츠 버전·모드 범위별로 표시하고 모의 완료를 실제 게시 집계에 섞지 않는다.

### B. Blog 수동 게시와 증거

승인된 blog 초안→manual_ready→제목/본문 복사(수동 복사 대안)→운영자가 외부에서 직접 게시→‘외부에서 게시를 마쳤습니다’ 선언→awaiting_evidence→게시 URL 또는 외부 ID, 대상 블로그/계정, 관찰 시각, 확인 방법/메모 검토→증거 저장 서버 확인→published. 복사·내보내기·게시 선언만으로 게시 확인됨을 표시하지 않는다. URL은 자동 크롤링하지 않으며 ID만이면 확인 방법 메모가 필요하다. 허용 호스트 정책은 최종 확정 대상이다. 실제 입력 예시는 제공하지 않는다.

게시 여부를 모르면 awaiting_evidence→unknown 대사로 이동한다. 중단은 사유와 외부 내용이 남을 수 있음 확인 후 abandoned다. abandoned가 멱등키를 점유하므로 ‘새 버전으로 우회’ CTA를 제공하지 않고 운영 검토를 안내한다.

### C. 원문 변경·승인 무효화

원문 저장으로 새 버전 생성→이전 버전을 참조한 초안은 ‘원문 변경 · 재승인 필요’→영향받는 미실행 예약은 stale 보류→버전 차이 확인→최신 원문 기준 새 초안 리비전→새 승인→이전 열린 작업의 안전한 취소/정리 후 새 작업 준비. 과거 문안으로 되돌려도 과거 승인이 부활하지 않는다. 과거 게시 증거·성공은 그대로 보존한다. 동시 편집 충돌은 기대 버전과 최신 버전을 비교하고 입력을 조용히 덮어쓰지 않는다.

### D. unknown과 재인증

작업 unknown→대사 상세→알려진 시도/계정/컨테이너·외부 근거 검토→검증된 조회 기능이 있을 때만 조회, 없으면 사람이 직접 확인→게시 확인 / 부재 확인 / 여전히 불명 기록. 조회 실패·검색 결과 없음·컨테이너 PUBLISHED만으로 자동 확정하지 않는다. unknown 화면·일괄 메뉴·상세 어디에도 재게시/복제 CTA를 두지 않는다.

confirmed_absent→failed(operator_only)는 **재게시 허가가 아니다**. 별도 권한 있는 운영자 재실행 승인에서 대사 기록·최신 승인·미디어 권리·연결/readiness·중복·전역 gate·시도 한도를 다시 검사한다. live gate가 닫혀 있으면 승인 후에도 실행하지 않는다. 실패/중단 작업이 다른 버전 작업을 막는 경우 작업 상세에서 기존 기록과 정리 정책을 안내하며 버전 변경 우회를 권하지 않는다.

reauth_required→연결 화면→향후 외부 인증→같은 계정 여부 확인→보류 작업 재검토. 재인증 완료는 unknown 해소나 예약 자동 재개를 뜻하지 않는다. 기한 지난 예약은 새 시각/지금 실행 확인/취소를 선택하게 하며 자동 일괄 실행하지 않는다.

## 5. 화면 명세와 빈 상태

HTML의 W1~W9가 아래 화면에 대응한다. HTML은 검토용 앵커 탐색만 하며 저장/선택/게시 기능을 시뮬레이션하지 않는다. 데이터가 없다는 사실을 DB 조회 0건으로 바꾸지 않고 ‘운영 데이터 미연결 · 표시할 항목 없음’으로 쓴다. W9의 상태 설명은 실제 사건이 아닌 명시적 상태 사전이다.

| 화면/경로 | 핵심 배치와 필드 | 다음 행동/빈 상태 | 경계·오류 |
|---|---|---|---|

| W9 준비 비교 `/contents/[id]/prepare` 및 상태 사전 | 채널 선택→채널별 버전·승인·대상·모드·차단 원인→개별 확인 | 선택 원문 없음. 지원하지 않는 live/예약 비활성 | 접수 응답 유실은 기존 작업 조회, 반복 게시 요청 금지. 성공 채널 재실행 없음 |

채널 편집은 Blog 제목/본문 분리, Threads 텍스트 우선, Instagram 캡션+단일 이미지 우선으로 정보 구성을 달리한다. Instagram 캐러셀·동영상과 다계정은 MVP 밖이다. 글자 수/이미지 제한은 공식 문서 분석 결과와 테스터 검증이 연결되기 전 확정 수치나 통과 배지를 만들지 않는다. 생성형 AI 초안 생성 기능도 구현 사실로 추가하지 않는다.

## 6. 상태 계약과 액션

서버 응답의 상위 상태, 단계, 보류, 경고를 구분한다. 현행 `PublishJob`에 없는 phase/hold/issues/readiness 필드는 후속 서버 DTO가 필요하다. UI가 임의 추론하거나 기존 타입에 없는 `published_with_issues`를 상위 status로 저장하지 않는다.

| 축 | 표시/조건 | 액션 |
|---|---|---|
| 검토 | draft/needs_review: 검토 필요; approved: 승인됨+버전·actor·시각 | 현재 버전 검토·승인. 서버 성공 전 승인됨 금지 |
| 최신성 | stale: 원문 변경 · 재승인 필요 | 차이 확인→새 리비전. 기존 예약 실행 차단 |
| 연결 | not_connected/reauth_required/connected 등 | 연결 설명/향후 인증. 기능 readiness와 따로 표시 |
| 기능 준비 | unverified / unsupported / supported+근거·시각·계정 범위 | 문서·모의 성공만으로 supported 승격 금지 |
| scheduled | 예약/즉시 대기, 시각+IANA 시간대·오프셋 | 준비된 서버에서만 변경/취소. 현재는 예약 준비 전 |
| dispatching | 실행 중, 확인된 단계만 표시 | 상세 조회; 정체되어도 즉시 실패/재시도 아님 |
| 단계(향후 DTO) | container_created/processing/ready/publish_requested/confirming | 단계 이력. ready는 게시 완료 아님 |
| published | 게시 확인됨+수락 증거 | 증거 보기, 수정은 정정 이력 |
| published_with_issues | 상위 published + issues. 게시 확인됨 · 구성 경고 | 게시 근거와 누락/구성 경고 함께 검토; 재게시 버튼 없음 |
| dry_run_succeeded | 모의 실행 완료 · 외부 게시 없음 | 미리보기 검토; 실제 게시 집계 제외 |
| manual_ready | 수동 게시 준비 | 준비된 서버에서 승인본 복사/수동 게시 안내 |
| awaiting_evidence | 게시 증거 대기 | URL/외부 ID와 확인 근거 입력(후속 구현); 게시 완료 오인 금지 |
| unknown | 결과 불명 · 대사 필요 | 대사만; 재게시/자동 재시도/복제 없음 |
| failed | 확정 실패+오류 요약+retry policy | auto는 서버 정책, operator_only는 별도 승인 검토, never는 재실행 금지. 단순 retryable로 CTA 생성 금지 |
| cancelled/abandoned | 취소 확정/수동 작업 중단 | 이력. 외부 게시 삭제 의미 없음, abandoned 키 점유 유지 |
| 보류/경고 | stale/reauth/rights/capability/paused/awaiting_operator | 원래 결과 옆에 이유·해결 위치. 전역 gate와 중지 상태 별도 |

현재는 Blog manual/dry_run 경로의 **설계·도메인만**, Threads API/연결 readiness 미검증, Instagram 단일 이미지 계획·연결/미디어/API 미구현·미검증이다. M1/M2 DB 미적용·미실행, live gate 닫힘을 항상 표시한다. 작업·연결·계정·실적·가격·예약 숫자는 만들지 않는다. 모드 선택에서 Blog live와 비Blog manual은 제공하지 않는다.

## 7. 디자인 토큰·접근성·공통 상태

기존 `design.css`에서 인용: `--ds-blue:#2563eb`, `--ds-blue-dark:#1e40af`, `--ds-blue-soft:#eff6ff`, `--ds-orange:#f97316`, `--ds-orange-ink:#9a3412`, `--ds-orange-soft:#fff7ed`, `--ds-ink:#172b4d`, `--ds-muted:#526178`, `--ds-line:#cbd5e1`, `--ds-paper:#fff`, `--ds-surface:#f7f9fc`, `--ds-error:#991b1b`, `--ds-error-soft:#fef2f2`, `--ds-radius:20px`, `--ds-content:1180px`. 본문 18px, 시스템 글꼴·Malgun Gothic, 줄높이 1.7. 주요 버튼 높이 50px, 필드 48px, 터치 타깃 최소 44px. 안내 파랑, 주의 주황 잉크, 오류 적색과 설명 텍스트를 함께 쓴다. 성공을 새 초록색으로 꾸미지 않는다.

HTML은 같은 토큰과 notice/card/empty 패턴을 자체 CSS로 사용한다. 앱 파일이나 외부 자산을 불러오지 않는다. 960px 탐색 재배치, 700px 한 열, 320 CSS px 줄바꿈, min-width:0, 긴 URL/ID overflow-wrap을 반영한다. 밀도가 높은 콘솔 h1은 기존 clamp 범위 안의 작은 크기로 조정 제안한다.

- 한국어 lang, 페이지별 h1 하나, main 하나, 본문 바로가기, 구별되는 nav 이름, 현재 링크 aria-current를 제공한다. HTML은 여러 화면을 한 문서에 놓으므로 화면별 h2를 사용한다.
- 이동은 실제 링크, 행위는 button. 링크형 채널 화면은 ARIA tab을 붙이지 않는다. 실제 탭 구현을 선택하면 화살표/Home/End·선택/포커스 분리 패턴을 별도 구현한다.
- 키보드 Tab 순서는 메뉴→현재 제목→필터→내용→검토/다음 행동이다. 전체 행 클릭에 의존하지 않는다. 로딩 갱신은 초점을 뺏지 않는다. 라우트 이동 후 제목, 확인 대화상자 종료 후 호출 버튼으로 포커스 복귀.
- 3px 파랑 focus-visible, offset 5px 유지. 모달은 제목·포커스 제한·Escape·안전한 첫 행동이 필요하다. 영구 disabled는 wait 커서를 쓰지 않고 옆에 사유/해결 링크를 둔다. disabled만으로 설명을 숨기지 않는다.
- 상태는 색·아이콘만으로 설명하지 않는다. label/legend와 오류 요약→필드 연결을 제공한다. 동적 완료만 role=status/aria-live=polite, 즉각 교정할 오류는 alert; 정적 샘플의 모든 경고를 live로 낭독하지 않는다.
- 미디어 설명·장식 구분, 드래그 대신 위/아래 이동 버튼. 고대비 forced-colors에서 테두리·포커스 유지, reduced-motion 반영. 200% 확대/리플로우 및 실제 대비는 후속 검증 필요이며 토큰 재사용만으로 통과 선언하지 않는다.

| 공통 상태 | 표시와 행동 |
|---|---|
| loading | 구획에 불러오는 중, aria-busy. 집계/연결 상태를 0이나 성공으로 임시 표시하지 않음 |
| empty | 실제 조회 성공 후 비어 있음 / 아직 데이터 경로 미연결 / 필터 결과 없음 세 경우를 구별 |
| error | 조회 실패 위치·안전한 코드·재조회. 이전 결과는 갱신 실패/마지막 확인 시각 표시. 게시 실패로 변환하지 않음 |
| disabled | 준비 전 사유·선행 조건·설명 링크. 샘플 HTML의 모든 행위는 비활성 |
| submitting | 행위별 진행 문구, 중복 제출 차단. 접수 응답 유실은 기존 작업 확인, 자동 재요청 없음 |
| conflict | 최신 서버 버전 재조회·차이 비교, 미저장 입력 유지 범위 설명. 늦은 증거 확정 덮어쓰기 금지 |

## 8. 구현 범위와 후속 Claude 개발 순서

**이번 산출물:** IA/메뉴/경로/권한/상태/와이어프레임/의존성만. **후속 프론트 범위:** admin shell, 원문·채널 초안·승인, 채널별 실행 준비, 연결 상태, 미디어 권리, 큐, 상세·수동 증거·대사 UI. **별도 백엔드 범위:** 인증·저장/RPC·RLS·연결/OAuth·미디어 처리·dispatch·스케줄러·감사. 현행 샘플 컴포넌트를 저장 가능한 운영 기능으로 이름만 바꿔 연결하지 않는다.

| 순서 | Claude 개발 작업 | 의존성과 확인 기준 |
|---|---|---|
| 1 | 배포 전용 접근 판정과 admin→콘솔 shell/안전한 빈 상태 | D1 서버·DB 판정, 보호된 메뉴/캐시, 미연결 데이터의 비노출 |
| 2 | 원문 버전·초안 리비전·승인 조회/저장 | M1 DB 검증/적용을 별도 승인 범위에서 완료, DTO·낙관적 버전 충돌·stale 처리. 서버 성공 전 저장/승인 표시 금지 |
| 3 | Blog manual·dry_run, 수동 준비/복사/증거 | M2 DB 검증/적용, 대응 RPC, 허용 URL/ID 정책. published 증거와 abandoned 점유 규칙 |
| 4 | 작업 상세·unknown 대사·늦은 증거·오류/재실행 승인 | 대사 저장·동시성·retry policy DTO, unknown 전체 CTA 차단. 서버가 live gate/hold 재검사 |
| 5 | 연결/readiness 표시와 인증 복귀 | 비밀 저장·OAuth 서버 모듈·계정 일치·기능별 검증 근거. 복귀 후 예약 자동 재개 없음 |
| 6 | Threads 텍스트, 이후 Instagram 단일 이미지 | 실제 계정/앱 권한/테스터 검증, clean-room 경계, 컨테이너 선커밋·대사, Instagram 미디어/권리 파이프라인 |
| 7 | 예약·운영 중지·지연 안내 | 스케줄러/비용 결정·운영 정책·상태 조회. live 별도 승인 전 비활성 |

구현 후 별도 작업에서 역할별 직접 URL 차단, 저장 실패/동시 변경, stale 승인, manual 증거, unknown 무재게시, 부분 결과·issues, 재인증/중지 복귀, 모바일/키보드/스크린리더/대비를 검증해야 한다. 이번 작업은 테스트·브라우저·네트워크·빌드·DB 실행을 하지 않는다.

D1(승인 admin), D2(부재 확인 후 운영자 재실행 승인)는 통합 플랜에서 이미 결정한 기준으로 재질문하지 않는다. 나머지는 구현 사실과 분리해 Master가 기존 승인·결정 문서와 대조한다. 디자인 완료는 live gate 해제를 의미하지 않는다.

## 10. 검토 한계

산출물 텍스트와 입력 계약을 정적으로 대조했다. HTML은 오프라인 단일 문서이며 외부 asset/script/form/API/계정 입력을 포함하지 않는다. 앵커·details 외 실행 동작은 없으며 데이터는 빈 상태와 명시적 상태 설명뿐이다. 렌더링·반응형 실측·접근성 도구·테스트·빌드·DB·외부 API 실행은 지시상 미실행이다. 저장·예약·연결·게시·운영 정상의 검증 결과로 사용할 수 없다. Git 초기화/커밋 및 앱·DB·다른 문서 수정 없음.
