## 목적과 역할

기존 콘텐츠 중심 A안 위에 관리자가 실제 저장 상태·작업 결과·차단 원인을 확인하고 허용된 조치만 수행할 수 있도록 서버와 관리자 기능을 완성한다. 디자인 선택·공통 셸 변경·프론트 배포는 Master에게 인계한다. 본 작업은 계획과 인수인계 문서만 작성하며 앱·SQL을 수정하거나 작업자를 새로 시작하지 않는다.

계획 완료 조건은 최신 구현과 미완료 구분, 실행 순서와 파일 경계, 서버/화면 계약, 검증 조건, 차단 해소 담당 및 Master 실제 전달이다. 구현 완료나 운영 연결 완료를 뜻하지 않는다.

## 서버와 관리자 페이지 계약

1. 페이지뿐 아니라 조회·서버 액션·RPC에서 세션 actor와 필요한 권한을 확인한다. 배포 콘솔은 승인 admin(D1)을 적용한다. 일반 관리자 업무도 승인 상태와 최소 필요 권한을 계약으로 명시하며 클라이언트 role/actor 입력을 신뢰하지 않는다.
2. 읽기는 `ok(data)` / `not_ready` / `denied` / `not_found` / `error`를 구분한다. `ok([])`만 0건으로 표시한다. 진단에는 비밀·본문·개인정보 대신 안전한 오류 코드와 시각을 쓴다.
3. 쓰기는 기대 버전/승인 해시를 전달하고 서버에서 최신성·소유권·상태를 재검사한다. pending 중 중복 제출을 막고 conflict/stale/uncertain에서 사용자 입력을 유지한다. 응답 유실 시 자동 재요청하지 않는다.
4. 연결 화면에는 계정 식별·채널·연결 상태·만료·확인 시각·가능 조치만 전달한다. credential 원문/암호화 봉투/서버 키는 DTO·HTML·URL·로그에 넣지 않는다. 재연결은 동일 계정 확인, 다른 계정은 새 연결이다.
5. 준비도는 저장소/인증/기능 검증/실행기/게시 허용을 분리한다. 계정 connected, 확장 입력 completed, 작업 생성 scheduled를 published로 표시하지 않는다. live gate는 계속 닫는다.
6. unknown/needs_check에는 자동 재게시·재인계 조치를 두지 않는다. 확인된 부재 후 재실행도 운영자 승인과 새 근거 없이는 실행하지 않는다. 관리자 판단의 actor/대상/사유/전후 상태·시각을 감사 기록에 남긴다.
7. 관리 화면은 동적·private/no-store를 유지한다. 로딩/빈 상태/오류/권한 거부/진행 상태/포커스 복귀를 각각 표시한다. 운영 오류는 사용자가 취할 조치로 안내하고 기술 진단은 별도 구획에 둔다.

## 파일 경계와 충돌 방지

- 서버: `web/src/server/distribution/**`, 필요한 `web/src/app/api/distribution/**`, 관련 tests 및 로컬 검증 러너. OAuth 경로명은 BA-04 계약에서 확정한다.
- 관리자 기능: `web/src/app/admin/**`의 조회·폼·서버 액션. 공통 A안 셸·전역 CSS·공개 프론트 디자인은 Master/디자인 담당과 조정 후 수정한다.
- 데이터 변경이 필요한 BA-04~06은 새 migration을 별도 검토한다. 기존 migration의 적용 여부가 불명확하면 덮어쓰지 않는다. 기존 090000의 NOT VALID FK 사전 점검·검증 절차를 포함한다.
- package/lockfile, 공통 폼, globals.css 및 기존 Claude가 사용하는 공유 파일은 점유 확인 후 한 담당자가 순차 수정한다. 배포 RELEASE-FRONT-018 상태는 최신 Master 배정으로 다시 확인한다.
- 공식 TEAM/WORKLIST/결정 문서는 Master가 갱신한다. 이 세션은 고유 계획/인계 문서만 변경한다.

## 후속 운영 조건 및 미정 결정

- 환경 담당: 승인된 테스트 관리자/테스트 DB·필요 설정의 준비 여부를 값 없이 확인한다. 키/env/비밀번호를 이 세션에서 열람·등록하지 않는다.
- Master: 현재 RELEASE 작업과 파일 점유, 로컬/배포 포함 범위를 확인하고 BA-01부터 기존 Claude에 순차 배정한다. 원본 키트 파생 코드의 배포 가능 범위를 확인한다.
- OAuth 구현 담당: 구현 착수 시 공급자 공식 문서로 redirect/scopes/응답·만료 계약을 검증한다. 이번 문서는 공급자 규격을 확정하지 않는다.
- 회원/거래: 승인 권한 부여 범위, 가격/목표/취소·환불/배송 정책 확정 전 실거래를 열지 않는다. 감사/내보내기는 개인정보 최소화와 수식 주입 방지를 포함한다.
- 공통 금지: 실DB 적용, 외부 게시, commit/push, 키·env·비밀번호 열람/노출. Master의 다른 세션에 대한 별도 배포 승인을 본 세션 권한으로 확대하지 않는다.

권장 다음 배정은 BA-00 현황 고정 후 BA-01 운영 개요와 BA-02 연결 관리다. 실제 세션에서 확인 가능한 기능부터 관리자에게 제공하고 그 뒤 OAuth와 모의 실행기를 연결한다.
